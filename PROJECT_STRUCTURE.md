# Project Structure

LearnNova is organized following standard ASP.NET Core MVC conventions, extended to support N-Tier architecture principles. 

Below is a detailed breakdown of the directory structure and the purpose of each folder.

---

## Directory Tree

```text
LearnNova/
├── Controllers/
├── Data/
├── Extensions/
├── Migrations/
├── Models/
│   ├── Entities/
│   ├── Enums/
│   ├── Lookups/
│   └── ViewModels/
├── Repositories/
├── Services/
├── Views/
├── wwwroot/
├── appsettings.json
└── Program.cs
```

---

## Folder Explanations

### `Controllers/`
Contains ASP.NET Core MVC controllers. These classes handle incoming HTTP requests, interact with the `Services` layer to execute business logic, and return appropriate `Views` or redirects.
- *Examples*: `AdminController`, `TeacherController`, `QuizEngineController`.

### `Data/`
Responsible for the Entity Framework Core context and database seeding.
- `ApplicationDbContext.cs`: Configures the EF Core model, relationships, and DbSets.
- `DbInitializer.cs`: Contains logic to automatically seed the database with initial data (like the Admin account and default Roles) when the application starts.

### `Extensions/`
Contains C# Extension Methods designed to keep configuration and setup code clean.
- For example, `IServiceCollection` extensions to neatly register all Repositories and Services in `Program.cs`.

### `Migrations/`
Autogenerated by Entity Framework Core. Contains the C# scripts used to create and update the SQL Server database schema over time to match the Entity classes.

### `Models/`
The core data structures of the application, divided into subfolders to maintain separation of concerns:
- **`Entities/`**: C# POCOs that map directly to database tables (e.g., `Course`, `ApplicationUser`).
- **`Enums/`**: Enumerations used across the application (e.g., `UserRole`, `DifficultyLevel`).
- **`Lookups/`**: Classes representing static or rarely-changing lookup data.
- **`ViewModels/`**: Data Transfer Objects (DTOs) specifically designed to pass exactly the data needed between Controllers and Razor Views, preventing over-posting vulnerabilities and separating UI requirements from database schema.

### `Repositories/`
Contains the Data Access Layer implementation.
- Abstracts `ApplicationDbContext` calls behind interfaces. 
- Controllers and Services do not query EF Core directly; they use Repositories to fetch and persist data.

### `Services/`
Contains the Business Logic Layer.
- This is where complex calculations, validation, and multi-step workflows live.
- *Examples*: `QuizService` for calculating scores, `CourseContentService` for organizing modules.

### `Views/`
Contains Razor Views (`.cshtml` files). These are the HTML templates that render the user interface. They are organized in subfolders matching their respective Controllers (e.g., `Views/Admin/`, `Views/Course/`).

### `wwwroot/`
The web root directory for static assets. Only files in this directory can be served directly to the browser.
- Contains CSS stylesheets, JavaScript files, images, and third-party libraries (like Bootstrap).

---

## Root Files

- **`Program.cs`**: The main entry point of the application. Configures the Dependency Injection container, sets up logging, configures EF Core and Identity, and defines the HTTP request pipeline (middleware).
- **`appsettings.json`**: The primary configuration file for the application, holding settings like the database connection string and environment variables.
- **`LearnNova.csproj`**: The MSBuild project file defining target frameworks, NuGet package dependencies, and build configurations.
